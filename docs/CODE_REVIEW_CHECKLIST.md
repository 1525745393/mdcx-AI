# MDCx 代码审查详细检查清单

## 📋 代码审查检查清单

本文档提供代码审查时的详细检查清单，按模块分类，方便审查者逐项检查。

---

## 一、代码风格检查

### 1.1 Python 代码规范

#### 1.1.1 格式规范
- [ ] **缩进和空格**
  - [ ] 使用 4 个空格缩进
  - [ ] 无混用 Tab 和空格
  - [ ] 行尾无多余空格
  - [ ] 文件末尾有一空行

- [ ] **行长度**
  - [ ] 单行不超过 120 字符
  - [ ] 长的导入或字符串有合理的换行

#### 1.1.2 命名规范
- [ ] **变量命名**
  - [ ] 使用 snake_case：`user_name`, `total_count`
  - [ ] 布尔变量使用 is/has/can 前缀：`is_valid`, `has_permission`
  - [ ] 常量使用全大写：`MAX_RETRY`, `DEFAULT_TIMEOUT`

- [ ] **函数命名**
  - [ ] 使用 snake_case：`get_user_info()`, `process_file()`
  - [ ] 名称有意义，能表达功能
  - [ ] 避免单字母名称（循环变量除外）

- [ ] **类命名**
  - [ ] 使用 PascalCase：`ConfigManager`, `FileProcessor`
  - [ ] 名称有意义，能表达类的职责
  - [ ] 避免无意义的类名如 `Manager`, `Handler`

#### 1.1.3 导入规范
- [ ] **导入顺序正确**
  ```python
  # 标准库
  import os
  import sys
  
  # 第三方库
  import requests
  from pydantic import BaseModel
  
  # 本地模块（相对导入）
  from . import utils
  from ..core import base
  ```

- [ ] **导入习惯**
  - [ ] 使用绝对导入（Python 3）
  - [ ] 避免 `from module import *`
  - [ ] 按字母顺序排列导入

## 二、代码结构检查

### 2.1 函数设计

- [ ] **函数长度**
  - [ ] 函数不超过 100 行
  - [ ] 复杂函数有清晰的步骤划分
  - [ ] 单一职责原则：每个函数只做一件事

- [ ] **参数设计**
  - [ ] 参数不超过 5 个
  - [ ] 过多参数应封装为对象/字典
  - [ ] 参数有类型注解
  - [ ] 参数有默认值

- [ ] **返回值设计**
  - [ ] 返回值类型一致
  - [ ] 错误时返回 None 还是抛出异常有明确规则
  - [ ] 多返回值使用命名元组或字典

### 2.2 类设计

- [ ] **类大小**
  - [ ] 类不超过 500 行
  - [ ] 方法不超过 20 个
  - [ ] 方法不超过 50 行

- [ ] **类职责**
  - [ ] 单一职责原则
  - [ ] 类名能表达职责
  - [ ] 避免上帝类（God Class）

- [ ] **继承设计**
  - [ ] 继承层次不超过 3 层
  - [ ] 优先使用组合而非继承
  - [ ] 子类覆盖方法时调用 super()

### 2.3 模块组织

- [ ] **模块大小**
  - [ ] 模块不超过 500 行
  - [ ] 相关功能放在一起
  - [ ] 避免循环导入

- [ ] **模块接口**
  - [ ] 公共接口清晰
  - [ ] 私有实现隐藏

## 📊 审查评分卡

### 问题严重程度分级

| 级别 | 标签 | 说明 | 处理要求 |
|------|------|------|---------|
| 严重 | 🚨 blocker | 阻塞性问题 | 必须修复 |
| 重要 | ⚠️ major | 重要问题 | 建议修复 |
| 一般 | 🔧 minor | 小问题 | 可选修复 |
| 提示 | 💡 nitpick | 格式问题 | 不影响合并 |
| 疑问 | ❓ question | 需要澄清 | 需作者回复 |

### 审查通过标准

```
✅ 通过条件：
  - 无 🚨 blocker 问题
  - ⚠️ major 问题 ≤ 3 个
  - 所有 ❓ question 已澄清

⚠️ 需要修改：
  - 有 🚨 blocker 问题
  - ⚠️ major 问题 > 3 个
  - 存在未解决的问题

❌ 拒绝合并：
  - 存在安全漏洞
  - 严重破坏现有功能
  - 违反项目核心原则
```
