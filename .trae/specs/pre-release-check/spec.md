# 发布前检查规范 (Pre-Release Checklist)

## 为什么需要检查

在发布新版本之前，确保所有功能完整、代码质量合格、没有遗漏的关键步骤。

## 检查范围

### 1. 代码完整性检查
- [ ] 所有修改的文件都已提交到 git
- [ ] 没有未提交的本地修改
- [ ] git 工作树是干净的
- [ ] 版本号已正确更新

### 2. 功能完整性检查
- [ ] 所有计划的功能都已实现
- [ ] UI 界面与功能需求一致
- [ ] 配置保存和加载功能正常
- [ ] 预览功能正常工作

### 3. 代码质量检查
- [ ] Python 语法检查通过
- [ ] 没有遗留的调试代码
- [ ] 代码风格符合项目规范
- [ ] 注释和文档完整

### 4. 配置检查
- [ ] 默认配置文件包含所有新字段
- [ ] 枚举类包含所有必要的选项
- [ ] 配置模型包含所有新字段
- [ ] 配置加载和保存逻辑正确

### 5. UI 检查
- [ ] 所有 UI 元素都已正确定义
- [ ] 信号连接正确无误
- [ ] 翻译文本完整
- [ ] 布局调整正确

### 6. Git 标签和发布
- [ ] 版本号已更新
- [ ] Git 标签已创建
- [ ] 标签已推送到远程仓库
- [ ] GitHub Actions 已触发

### 7. 文档和更新日志
- [ ] changelog.md 已更新
- [ ] 功能说明完整
- [ ] 版本信息准确

## 影响范围

### 受影响的文件
- mdcx/consts.py - 版本号
- mdcx/config/enums.py - 枚举类
- mdcx/config/models.py - 配置模型
- mdcx/core/vsmeta.py - 核心逻辑
- mdcx/views/MDCx.py - UI 界面
- mdcx/controllers/main_window/*.py - 控制器
- resources/config/default_config.json - 默认配置

### 受影响的功能
- VSMETA 生成功能
- 自定义模板功能
- 配置管理功能
- UI 预览功能

## 检查流程

### 阶段 1: 代码完整性
1. 运行 `git status` 检查工作树状态
2. 运行 `git log --oneline -5` 查看最近提交
3. 运行 `git diff` 检查未提交的更改
4. 验证版本号正确性

### 阶段 2: 功能验证
1. 检查枚举类完整性
2. 检查配置模型字段
3. 验证核心逻辑实现
4. 检查 UI 元素定义

### 阶段 3: 代码质量
1. Python 语法检查
2. 代码风格检查
3. 审查关键代码段

### 阶段 4: 发布准备
1. 更新 changelog.md
2. 创建并推送 git 标签
3. 验证 GitHub Actions 触发
4. 监控构建状态
